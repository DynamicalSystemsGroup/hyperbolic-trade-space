## Purpose

His words: the top-level index "needs basic SEO and preview machinery", "the doc site probably does too", "formal
metadata that other systems expect to see when handling public links".

## Goals

- G1. One source of values: the site's name (`tradespace`), the one-line description (the posynomial invariant form
  as the formal basis, from `pyproject.toml`'s description or `CITATION.cff`'s abstract, one of them chosen and the
  other read from it), the public address (`https://dynamicalsystemsgroup.github.io/tradespace/`), the author and
  ORCID, the licence, the repository address, a preview image (the planted ternary, light scheme, at a size link
  handlers accept, 1200 by 630 px, generated by `scripts/build_site_figures.py` or a sibling), read by the composer
  and by the docs theme from one place (the interface contract's manifest or a small TOML beside it; the unit's
  default).
- G2. The root page, the history page and the abstract page (composed by `scripts/assemble_site.py`) carry: `<meta
  name="description">`, `<link rel="canonical">`, Open Graph (`og:title`, `og:description`, `og:url`, `og:image`,
  `og:type`, `og:site_name`), Twitter card (`summary_large_image`, title, description, image), and JSON-LD
  (`SoftwareSourceCode` for the package with name, description, codeRepository, license, author with ORCID,
  version, programmingLanguage; `WebSite` for the site).
- G3. Every docs page carries the same fields from the theme (a `main.html` override of the Material theme, or the
  theme's own `site_description`, `site_url` and social settings where they suffice), per-page title and the page's
  first paragraph or the site description as the description, canonical from `site_url`.
- G4. `robots.txt` allowing everything and naming the sitemap; a `sitemap.xml` for the whole site (the docs'
  generated sitemap plus the root pages), emitted by the composer.
- G5. A test, `tests/test_site_metadata.py`, that stages the site and asserts the fields on the root page, the
  abstract page and three docs pages, that every `og:image` and canonical resolves (200 on the staged server), and
  that the JSON-LD parses and names the version in `pyproject.toml`.
- G6. The pinned paper's pages (a myst build) are the paper branch's concern and out of scope here; the abstract
  page is in.

## Non-goals

No analytics, no tracking, no third-party scripts; no social-card plugin that adds a system dependency (Cairo) to
the docs build; no change to the pages' visible content; no change to the paper's build.

## Requirements and checks

| ID | Requirement | Check |
|---|---|---|
| R-1 | Every page served by the staged site has description, canonical, `og:title`, `og:image` | the test over the staged tree |
| R-2 | The values agree with `pyproject.toml` (version, description) and `CITATION.cff` (author, ORCID, licence) | the test |

| R-4 | No new Python dependency; lint, format, the fast suite, the strict docs build and the site tests green | the usual checks |

## Definition of good

A link to any page of the site unfurls with the right title, line and image in a chat client, and a search engine
indexes the site with its description and canonical addresses.

## Definition of good enough

G1 to G5 landed on `dev` with R-1 to R-4 met.

## Definition of done

Good enough met; one external preview check after the deployment (post-release, the punch list).

## Open decisions

None.

## Agent's defaults

- The values live in the interface contract's manifest under a `site.metadata` table (an additive amendment) if
  the contract's rules allow an additive key without a version bump, else a small `site/metadata.toml` (default).
- The description is `pyproject.toml`'s; `CITATION.cff`'s abstract is checked equal by the test (default).
- The preview image is a 1200 by 630 render of the planted ternary with the site's name, written by
  `scripts/build_site_figures.py` to `site/preview.png` (default).

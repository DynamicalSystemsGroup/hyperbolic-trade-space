# WP23 round 1: the diagnostic pair of `cubesat_r2.sysml`

This folder holds round 1 of the model-realism loop (D-6): the two views of the model (`INTENT.md`
states what each should say; generated by the views generator, see there), the coverage table
(`coverage.md`, copied from `examples/adcs/model_v2/views/`), the K = 1 exponent heatmap across
tau (`heatmap.png`, the primary regime; `heatmap_stock.png`, the baseline regime) and the K = 1 and
K = 3 record (`k3_record.md`). The texture hypothesis is checked here, not targeted: the lists below
state what is at zero exponent, and nothing in the model, the data or the fit was chosen to move them.

## How the pair was generated

The two datasets were generated on the host (not in the container; only the final regeneration runs
in `hts-paper`) through the experiments runner, into a scratch root that mirrors the repository's
paths with the model and the three code files linked from the `wp23case` worktree, so that nothing
was written under `examples/adcs/data/v2`:

```
R=<scratch>/wp23-round-1
mkdir -p $R/root/examples/adcs/{model_v2,experiments,data/v2}
ln -s <wp23case>/examples/adcs/model_v2/cubesat_r2.sysml      $R/root/examples/adcs/model_v2/
ln -s <wp23case>/examples/adcs/experiments/cubesat_oracle.py  $R/root/examples/adcs/experiments/
ln -s <wp23case>/examples/adcs/experiments/feasibility.py     $R/root/examples/adcs/experiments/
ln -s <wp23case>/examples/adcs/adcs_sim.py                    $R/root/examples/adcs/
cd <wp23case>
EXPERIMENTS_MODEL=examples/adcs/model_v2/cubesat_r2.sysml PYTHONPATH=examples/adcs \
  uv run python -m experiments --root $R/root --ledger $R/ledger.jsonl run v2-primary
EXPERIMENTS_MODEL=examples/adcs/model_v2/cubesat_r2.sysml PYTHONPATH=examples/adcs \
  uv run python -m experiments --root $R/root --ledger $R/ledger.jsonl run v2-baseline
```

Workers: the oracle's default, one fewer than the machine's 10 cores. Wall time: `v2-primary`
122 s, `v2-baseline` 115 s (2026-11-10 03:23 to 03:27 UTC, macOS 26.5.2 arm64, opensysml 0.12.1,
numpy 2.5.4, scipy 1.18.1). The ledger of the run is `generation-ledger.jsonl` here (the scratch
root is outside a repository, so its commit fields are null; the model, code and output hashes are
recorded). Each table has 1000 rows and 33 columns, no slew-time column; the header is the
committed v2 header less `slew_time_s` and `slew_time_05deg_s`:

```
design_id,seed,wheel_class,st_grade,panel_span_m,battery_wh,Kp,Kd,settling_time_s,
pointing_error_deg,total_mass_kg,adcs_mass_kg,control_effort,power_margin_w,energy_balance_wh,
eclipse_reserve_wh,peak_slew_power_w,dod_eclipse,settled,momentum_ok,torque_saturated_frac,
power_ok,dod_ok,peak_momentum_nms,panel_mass_kg,battery_mass_kg,generated_power_w,
available_power_w,usable_torque_nm,slew_loss_energy_wh,slew_deg,t_end_s,max_step_s
```

Output sha256: `adcs_designs_cubesat_gains.csv` (primary) `336288e57a23...`,
`adcs_designs_cubesat.csv` (baseline) `4cb65a2ffde1...` (full hashes in the ledger). Feasible
designs (the three flags of the case spec and every attribute positive): 706 of 1000 primary, 780

The pair was then drawn by `examples/adcs/model_v2/diagnostic_pair.py` from those two files and
the metric list of `examples/adcs/model_v2/views/coverage.csv` (nine traded metrics):

```
uv run python examples/adcs/model_v2/diagnostic_pair.py \
  --dataset $R/adcs_designs_cubesat.csv --gains $R/adcs_designs_cubesat_gains.csv \
  --coverage examples/adcs/model_v2/views/coverage.csv --out work-packages/WP23-rounds/round-1
```

## Before and after: the metrics at zero exponent across tau

The exponent is the K = 1 fit's at each of the figure's thirteen temperatures (twelve log-spaced
from 3 to 1000, and infinity); "at zero" means at most 1e-3 at every one of them, the figure's own
threshold for a metric with an exponent.

| Regime | Before (the paper's `fig-tau-sweep.png`: the frozen data, ten metrics) | Round 1 (`cubesat_r2.sysml`, event-detected settling time, nine metrics) |
|---|---|---|
| primary (aggressive gain box) | settling time, power margin, eclipse reserve, peak slew power | power margin, eclipse reserve, peak slew power |
| baseline (stock gain box) | total mass, peak slew power | peak slew power |

The "before" column was recomputed on the frozen data with the same sweep (the primary list is the
four the scope names). On the round-1 primary heatmap the settling time carries an exponent at
every tau (0.136 at the selected tau 38.1); on the round-1 baseline heatmap the total mass carries
one at the three smallest temperatures only (tau 3 to 9; zero from tau 15 on, and at the selected tau 45.7). The
K = 1 contending sets at the selected temperatures are in `k3_record.md`: primary, a 5-lemma
(total mass, energy balance, pointing error, depth of discharge, settling time); baseline, a
5-lemma (control effort, settling time, power margin, pointing error, depth of discharge).

## A finding for the record

On the primary regime the K = 3 report (`case.facet_table`, the contending set and tensions per
term) refuses at both of its documented bands: at the K = 1 band 1/tau = 0.0263 the cell of term 1
has 3 near-frontier designs, at the K = 3 fit's own band 1/tau = 0.0088 the cell of term 1 has 7,
against the report's minimum of 10. `k3_record.md` quotes both refusals and gives the K = 3 fit
itself (the exponents per term, the rows and shares of the cells) from the estimator; the report
table is given for the baseline regime, at the K = 1 band. Nothing was changed to obtain a report;
the band is a reading parameter, and the modeller and the PM decide how the round reads it.

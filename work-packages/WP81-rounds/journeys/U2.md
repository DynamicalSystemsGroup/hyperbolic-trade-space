# U2, the analyst whose table comes from a model (home, getting-started, overview, conditioning, fitting, examples)

**1. Home.** (a) I wanted to know whether my model matters and how to connect it. The second bullet, "Bring my own
system model, and know what must hold", is aimed at me. (b) The only paper pointer is "The paper makes the argument
for the method; the project page links it". I expected the full argument there. I did not expect that the link lands
on an abstract. (c) Say what the paper is: "The paper (working draft; abstract online, full text built from the
repository) argues for the method." Or drop the sentence and keep only the project page link. I don't need the
argument to run a fit. (d) The sentence "tells you ... where the table has white space" and the PCA line "PCA finds
where the data spread, this finds where they stop" read like paper framing. The PCA line is still useful because it
places the package for sklearn users. (e) I could not tell where the "system model" bullet leads. "Posynomial
invariant form" and "reference surface" are undefined on first read.

**2. Getting started.** (a) The install and first fit work for me. I looked for model guidance. (b) There are no
paper links. Pointers go to the temperature, prediction, conditioning and limitations pages. (c) Nothing to change
about the paper here. (d) Nothing. (e) The key line is "the evaluation stays outside the package, which never calls
your model". That answers how to connect, but it is buried in a bullet. "Pareto boundary" is used without
explanation. I also don't know what "prediction takes them" means for my configuration variables.

**3. Overview.** (a) I wanted the model's role in the method. (b) No paper pointer. (c) None needed. (d) The PCA
contrast ("trade-offs, not variance") is argument. It is short enough to stay. (e) The pipeline says the package
covers "the last three" stages and "never sees how" attributes are made. That is the most direct answer to "does the
model side matter". It says the model does not matter to the package, but it does not say what it must give me
(positivity, feasibility, enough sample coverage). Where the model sits, "System model" is never mentioned.
"One-time normalization" is unexplained.

**4. Conditioning.** (a) I wanted to know how my simulator outputs become metrics. (b) No paper pointer. (c) None.
(d) "A stable fitted direction answers that question as conditioned and is not a context-free discovery" is a
methodological position. A user needs it, but it is stated abstractly. (e) Orientation, shift and scaling are clear.
I would want one line on simulator failures and NaN, since "Infeasible rows ... failed to evaluate" is the only note.
No guidance on a model with noise or stochastic output.

**5. Fitting.** (a) I wanted to know whether the fit depends on how the table was produced, for example sampling
design. (b) No paper pointer. (c) None. (d) The multi-term temperature, "term planes are not supporting planes" and
kappa paragraphs are dense method detail. Much of it is paper or theory material, not first-use documentation. (e)
"Supporting envelope", "term_temperature" and "not bracketed" assumed prior knowledge. Nothing on sample size or on
how the sampling scheme affects the result.

**6. Examples.** (a) This is the one page with a SysML v2 system model: "described by a SysML v2 system model... the
model and the data are in examples/adcs/". I wanted to know how that model produced the table. (b) No explicit paper
link. The only pointer is to "From the chart back to a design". (c) Nothing on the paper. But the page says "the slew
is simulated and the model computes the rest" and never shows the model-to-table step. I would want a sentence or
link saying where the SysML model is and how a row is generated, or the plain statement that the example starts from
the data. (d) "The triples are not findings", the requirement price table and the case narrative ("What the fit
says") read as paper results rather than a tutorial. (e) The page mixes one cubesat case and a synthetic three-metric
case that repeats the home page figures. "7-lemma" is unexplained. "Price in band widths" is opaque. The requirements
and "design_sets" tables are hard to read as text. The page is long.

**My take.** I know the package never calls my model and the model side is only an upstream table builder. I do not
know whether model fidelity or sampling matters, nor how to connect a SysML model. Examples is the only hint, and it
stops at the data. I stopped on Home at the second bullet, which leads to Getting started's "Your own data" and then
the conditioning page. I backtracked to Overview for "what is covered" and found no model-fit guidance there either.
A paper reader or reviewer would want the paper link to say it is a draft and where the full text is. A methods
reader would want the PCA contrast and the conditioning position on this site. A script user wants only the install
and first fit.
